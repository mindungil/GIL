# gil v0.2.0

Released 2026-05-12.

## What is gil

gil is a continuous coding harness. You describe the work in natural
language, the agent decides every verb via tool calls, and the daemon
keeps running until the task is finished — not until a timer trips or
the next prompt arrives.

v0.2.0 is the first version where `gil` (no subcommand, no slashes) is
the canonical entry point. The pre-alpha interview / slash-command
split is gone.

## Highlights

- **Single surface.** `gil` opens a chat. The agent reads, edits, runs,
  verifies, and delegates by calling tools. Slash commands are not
  hidden — they no longer exist.
- **Verify-loop discipline.** `plan_steps` declares the work, `verify`
  runs each step's acceptance command, and a step's `verified` status
  flips only when verify succeeds. Status transitions are
  system-enforced; the agent cannot self-grade.
- **Subagent delegation.** `spawn_agent` / `wait_agent` /
  `agent_status` let a parent split work across short-lived children
  with their own sliced spec and budget. Caps: 8 concurrent children
  per root, depth 1.
- **MCP, finished.** The spec-pinned MCP-server allowlist now actually
  launches subprocesses, surfaces their tools to both chat-mode and
  run-mode, and shares one subprocess set across mode handoffs.
- **giltui Agent Tree.** The mission-control TUI renders the agent's
  tool-call timeline next to the existing sessions / spec / activity
  panes. One stream, one timeline, regardless of mode.

## Install

```bash
git clone https://github.com/mindungil/GIL.git && cd GIL
make install     # /usr/local/bin/{gil,gild,giltui,gilmcp}
```

Pre-built binaries (linux/macOS amd64+arm64) ship via GoReleaser on
tag. See the Release page on GitHub.

## Upgrade

v0.2.0 is the first non-alpha. There is no in-place upgrade path from
v0.1.0-alpha — uninstall the old binaries, install v0.2.0, and run
`gil init` again. Session DBs from v0.1.0-alpha will not load because
the schema is now v3 (parent linkage + plan_steps).

## Provider matrix

Anthropic native (claude-opus / sonnet / haiku 4.x).
OpenAI-compatible adapter (OpenAI, OpenRouter, vLLM, Ollama).

## Known limitations (post-v0.2 roadmap)

- WorkingSet (`add_to_workingset` / `list_workingset`) is in-memory
  per daemon lifetime. Restart → empty.
- Chat surface is single-column; the multi-pane M6 Option B/C
  redesign is gated on a user decision.
- Real-LLM provider hardening (VCR cassettes, long-run stress, cost
  catalog auto-update) tracked separately.
- Reasoning split + typed-action pipeline (typed `AssistantOutput`
  proto) deferred — current surface uses plain text + tool_call/
  tool_result Parts.
